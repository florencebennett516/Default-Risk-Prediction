## 唯一最终口径

最终报告采用 90 个特征，按完整放款月份划分：训练期 2007-06 至 2016-03，验证期 2016-04 至 2017-06，测试期 2017-07 至 2018-12；测试集为 79,898 条。分类阈值 0.5 下，同口径基线 AUC 为 0.7220，验证期选定的调优模型 AUC 为 0.7198。

早期随机划分实验的 XGBoost 为 335 特征、测试集 160,000 条、AUC 0.7330，不能写成最终模型成绩。模型不因测试分数高低而事后改选，调优也未证明优于同口径基线。

## 运行条件与缺失输入

**仅克隆仓库不能直接执行完整流程。** GitHub 版本未提供原始贷款 CSV、清洗快照、特征矩阵、最终模型及其同版本预测和汇总文件。本地可能保留的早期特征矩阵不能替代最终流程输入。需通过合法渠道取得原项目同版本输入，具体约定见[数据说明](../../data/README.md)。

补齐输入后，流程代码支持以下两种模式：

1. `RUN_TRAINING=False`：重放已有模型，依赖本地 `results/xgboost_optimization/` 的模型、预测及汇总文件。该路径是代码的输入约定，不是仓库交付目录；没有这些文件不能运行此模式。
2. `RUN_TRAINING=True`：重新执行训练窗口内特征处理、5 折时间验证、Optuna 搜索、验证期选型、合并再训练和测试。它仍依赖原始数据和清洗快照；代码生成的时间戳结果目录是运行产物，不能当成当前已有文件。本次未执行该分支。

打开 notebook 后选择已安装依赖的 Python 内核，仅在输入补齐后从第一个单元格依次执行。若数据或预测核验失败，应检查输入、模型与预处理模块是否同版本，不要删除断言强行继续。

Notebook 依赖 `code/model/` 中的自定义预处理、评估和报告模板，不是可单独复制的独立文件。重放会更新报告及分析产物；历史保存输出不代表新机器上已经执行成功。
