## 1. 实验思路与阶段成果

### 1.1 围绕业务问题推进实验

**问题场景。** 贷款审批既要识别高风险客户，也要保留业务规模。如果一味提高拒绝比例，风险指标可能改善，但会损失正常客户；如果只使用默认分类阈值，又容易遗漏大量违约客户。

**项目目标。** 建立可对后续月份客户进行风险排序的模型，并在拒绝规模受控的前提下，选择风险更低的通过客户组合。

**实施路径。** 从数据清洗和特征构造入手，经过模型选型、时间验证和参数优化，再将风险评分转化为容量受限的客户筛选策略。各环节按“问题—目标—行动—结果”推进。

| 业务问题 | 实验目标 | 采取的行动 | 阶段结果 |
| --- | --- | --- | --- |
| 历史模型能否用于后续月份客户 | 检验跨时期风险区分能力 | 按放款月份划分样本，采用 {cv_folds} 折时间验证 | 测试 AUC 为 {auc:.4f}、KS 为 {ks:.4f}，形成按时间评价的风险评分方案 |
| 原始信息如何转化为风险信号 | 提升对偿债压力和客户差异的识别 | 构造偿债能力、信用账户及聚合特征，完成筛选和 {n_trials} 次参数搜索 | 交付 {feature_count} 个特征的模型；调优测试 AUC 未超过基线，后续优先检验策略价值 |
| 默认阈值识别的违约客户过少 | 在控制拒绝规模的同时降低通过组风险 | 从固定 0.5 改为验证集容量约束下的坏率最小化搜索 | 应用阈值为 {applied_threshold:.4f}，测试 Recall 为 {applied_recall:.2%}、通过组坏率为 {applied_pass_bad_rate:.2%} |
| 业务团队如何使用评分 | 将模型输出转化为复核优先级 | 分析风险十分档和关键特征，形成分层处理建议 | 最高风险档覆盖约 {top_coverage:.2%} 客户，捕获 {top_capture:.2%} 的违约，可作为重点复核队列 |

## 2. 业务解读与阈值策略

### 2.1 风险分层：把复核资源用在重点客户上

测试期总体违约率为 **{test_bad_rate:.2%}**；最高风险 10% 客户的违约率为 **{top_bad_rate:.2%}**，最低风险 10% 为 **{bottom_bad_rate:.2%}**。这表明评分能够将不同风险水平的客户分开，为复核资源分配提供依据。

{risk_table}

建议按以下方式进入业务试点：

| 业务环节 | 评分的具体用途 | 重点观察指标 |
| --- | --- | --- |
| 贷前复核 | 高分客户优先进入人工核查，重点核对收入、负债与申请信息 | 复核命中率、处理时长、正常客户误拒 |
| 审批辅助 | 在既有政策下结合风险评分判断，分别记录模型建议与人工结果 | 拒绝比例、通过规模、通过组坏率 |
| 贷后关注 | 将申请时评分作为初始风险分层，结合后续还款信息安排关注 | 同账龄逾期、回收情况、管理成本 |

**业务价值在于提高资源分配效率。** 先让复核人员关注高风险队列，再通过实际反馈判断是否值得扩大应用；模型分数不直接替代人工审批。

### 2.2 阈值调整：从默认分类转向客户组合管理

原 0.5 阈值只标记测试客户的 {flagged_rate:.2%}，Recall 为 {recall:.2%}。针对覆盖不足，本轮将目标调整为：**验证集拒绝率不超过 {max_rejection_rate:.0%}，在可行阈值中选择通过组坏率最低者。** 不再预设 5% 坏率门槛，也不要求必须用满拒绝额度。

阈值仅依据验证期选择，锁定后应用于测试期。拒绝率按拒绝组笔数占比计算，通过组坏率按通过组违约笔数占比计算。

| 核心指标 | 测试表现 | 管理含义 |
| --- | --- | --- |
| 应用阈值 | {applied_threshold:.4f} | 将连续评分转化为客户筛选规则 |
| 拒绝比例 | {applied_rejection_rate:.2%} | 与 {max_rejection_rate:.0%} 的容量上限核对，判断客户保留规模 |
| 违约捕获率 | {applied_recall:.2%} | 观察筛选规则覆盖多少违约客户 |
| 通过组坏率 | {applied_pass_bad_rate:.2%} | 与测试总体 {test_bad_rate:.2%} 对照，评价保留组合的风险水平 |

**验收顺序是先看规模，再看风险，最后看成本。** 拒绝比例超限，就说明固定阈值的跨期容量表现未达标；容量满足后，再评价通过客户的风险和正常客户流失。当前结果体现历史客户筛选效果，真实降损与利润贡献在试点中核算。

### 2.3 特征解释：为人工核查提供线索

模型主要结合信用评级、偿债负担、信用水平和账户信息进行评分。既有评级及其交叉统计约占绝对 SHAP 总量的 {rating_share:.2%}，说明模型较多利用原有评级体系的信息，再结合其他特征进行排序。

| 信息类型 | 业务解读 | 建议核查方向 |
| --- | --- | --- |
| 信用评级及 FICO | 反映已有信用水平和风险分层 | 对照既有评分，检查新增模型是否补充了有效信息 |
| 收入、DTI、贷款收入比 | 描述偿债负担与借款需求的匹配情况 | 核实收入、负债和贷款申请材料的一致性 |
| 借款期限及账户信息 | 反映期限安排和信用账户差异 | 分期限、分客群观察表现，避免用整体均值掩盖差异 |
| 匿名及类别编码字段 | 提供辅助评分信息 | 完善字段定义，核实使用时点和业务解释 |

特征解释用于确定“优先核查什么”，不直接推导单一变量的拒贷规则。

## 3. 下一阶段计划与决策建议

### 3.1 建议推进小范围辅助复核试点

下一阶段的工作重点，从继续追求离线最高分，转向检验 **“容量可控、客户质量改善、处理成本可接受”**。建议先采用人工复核辅助模式，保留现有审批政策，通过反馈比较模型建议与实际处理结果。

| 优先级 | 下一步工作 | 验收要求 |
| --- | --- | --- |
| P0 | 明确标签定义、观察期限和字段获取时点，补充新的时间外样本 | 不同月份、期限客户按同一口径评价 |
| P0 | 固定拒绝率上限与坏率最小化目标，检查阈值跨期表现 | 同时报告拒绝比例、通过组坏率和正常客户误拒；明确超限处理方式 |
| P1 | 开展小范围辅助复核，记录人工处理及后续结果 | 量化命中率、处理量、客户流失及成熟后的风险表现 |
| P1 | 在相同拒绝规模下比较基线与调优模型 | 判断新模型是否值得增加实施和维护成本 |
| P2 | 建立月度监测和反馈机制 | 跟踪分数、字段、拒绝比例及延迟风险标签的变化 |

### 3.2 需要管理层确认的事项

- **应用范围：** 是否同意以人工复核辅助为首个试点场景，不直接切换自动审批。
- **规模口径：** 明确 {max_rejection_rate:.0%} 上限按什么业务批次统计，以及跨期超限时的处置流程；人工复核量另行安排。
- **投入与验收：** 明确复核资源、正常客户机会成本、试点规模和验收周期，以客户质量与成本的综合结果决定是否扩展。

**结果使用说明：** 本报告依据截至 2018 年的历史贷款样本；当前策略尚需新时期数据验证。固定概率阈值在验证期满足容量约束，不保证后续批次自动满足；历史筛选效果与真实经营收益分开验收。

### 3.3 汇报结论

本阶段完成了从贷款数据到风险评分、客户分层和业务阈值的交付。实验已明确两个方向：一是风险评分可以为高风险客户优先复核提供支持；二是阈值应围绕客户保留和通过组质量设计，而不是沿用默认 0.5。

**建议将下一阶段资源优先投入新样本验证和辅助复核试点，以拒绝规模、通过客户质量和处理成本作为是否扩大应用的决策依据。**
