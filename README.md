# 信贷违约预测

面向贷款违约识别的机器学习实践项目，包含数据清洗、特征工程、逻辑回归 / 随机森林 / XGBoost 对比、时间切分调优、阈值分析及项目报告。

**最终结果以[最终项目报告](docs/最终报告/最终项目报告.md)为准；流程代码见 [code/main_pipelin.ipynb](code/main_pipelin.ipynb)。**

> 项目已有离线实验与报告，但不是已上线的信贷审批系统。本次于 2026-11-11 统一文档口径，没有重训模型或重算指标。仓库不提供最终模型及完整重放输入，不能仅凭克隆仓库直接运行完整流程。

## 最终结果与历史实验

**最终报告采用按完整放款月份划分、90 个特征的 XGBoost 方案**：训练期为 2007-06 至 2016-03，验证期为 2016-04 至 2017-06，测试期为 2017-07 至 2018-12；样本量分别为 558,371、161,731、79,898。以下指标摘自[最终项目报告第 1.2 节](docs/最终报告/最终项目报告.md#12-最终测试指标与基线对比)，分类阈值为 0.5：

| 模型 | 测试 AUC | KS | PR-AUC | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 同口径基线 XGBoost | 0.7220 | 0.3270 | 0.3793 | 0.5093 | 0.0966 | 0.1624 |
| 最终报告选定的调优 XGBoost | 0.7198 | 0.3263 | 0.3756 | 0.5304 | 0.0669 | 0.1188 |

模型按验证期表现选定；调优模型测试 AUC **低于**同口径基线，不能表述为“调优全面提升效果”，也不能事后按测试分数改选模型。时间稳定性、阈值分析和局限见最终报告。

| 实验阶段 | 划分与特征口径 | 测试样本数 | XGBoost 测试 AUC | 现有依据 |
| --- | --- | ---: | ---: | --- |
| 早期三模型基线（非最终结果） | 按标签分层随机划分，65% / 15% / 20%；XGBoost 335 特征 | 160,000 | 0.7330 | [历史对比报告](docs/model/三模型对比报告.md)、[历史全部指标 CSV](docs/model/三模型全部指标.csv)、[历史测试指标 CSV](docs/model/三模型测试集指标.csv) |

## 策略建议与业务落点

- **cutoff 参考线：0.2275。** 历史验证 / 测试拒绝比例约 30%–35%，测试通过组坏率 **12.40%**，对比总体 **19.93%**。这是固定阈值的回测结果。
- **人工复核：最高风险 10%。** 该组违约率 **44.61%**、Lift **2.24**，捕获 **22.38%（约 22.4%）**的违约。
- **容量规则：建议改为 Top-K 分位队列。** 固定 cutoff 的拒绝比例由验证期 **29.99%** 升至测试期 **34.63%**，超出 30% 预算；按批次申请量和人力预算限制 K，入队与实际拒绝分别统计。Top-K 尚待等容量回测。
- **监控：通过率、通过组坏率、vintage 30+ / 60+ DPD、PSI。** 优先排查 **n14（PSI 0.5269）**与 **revolUtil（PSI 0.2048）**；vintage 指标需补齐还款与逾期数据后计算。

完整执行建议见[一页策略建议 memo](docs/最终报告/策略建议memo.md)；模型对照、bootstrap 区间与 PSI 表见[管理层决策汇报](docs/最终报告/项目汇报_管理层版.md)。

## 项目流程

1. 从原始贷款记录执行确定性清洗，并核对已保存的处理数据。
2. 按放款时间划分训练、验证和测试集，避免把早期探索实验与最终评估口径混为一谈。
3. 在训练窗口内处理缺失、类别编码、分组聚合、交叉特征和特征筛选。
4. 对比基线与调优模型，通过时间交叉验证和验证集选择参数及模型。
5. 在验证集研究分类阈值与复核容量，再评估测试期表现。
6. 输出审计表、特征解释、风险分层、图表和最终报告。

具体行为以主 notebook 和 `code/model/` 中的实现为准。早期 notebook 与周报用于展示项目迭代，不代表同一口径下的最终结果。

## 运行方式与边界

**GitHub 版本不包含贷款原始 CSV、清洗快照、特征矩阵和最终模型。** 本地可能保留的早期特征矩阵也不能替代最终流程输入。当前可直接阅读报告、历史指标和 notebook 代码；完整运行条件见[使用说明](docs/最终报告/使用说明.md)和[数据说明](data/README.md)。

1. 阅读流程：打开 `code/main_pipelin.ipynb` 查看代码；GitHub 中的 notebook 已清理执行输出。本次文档更新没有重新运行模型。
2. 默认 `RUN_TRAINING=False` 是**已有模型重放**。它需要合法取得原始数据、清洗快照及同版本模型、预测和汇总文件；仓库未提供完整输入，不能直接重放。
3. 设为 `RUN_TRAINING=True` 是**重新训练**，仍须补齐原始数据、清洗快照和依赖。代码会生成带时间戳的结果目录，该目录属于运行产物，不是现有仓库文件；本次未执行。

主 notebook 会向上查找项目数据路径。部分早期实验仍含 `D:/credit` 绝对路径或相对于 `code/` 的输入路径；它们是历史实验，不是推荐的跨机器运行入口。此轮未为整理文件而修改其模型逻辑。

`code/model/` 中的自定义变换模块和报告模板必须随项目保留；不能只复制单个 notebook 作为完整项目。
